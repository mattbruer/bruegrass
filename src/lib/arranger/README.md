# The arranger

The `/arranger` page turns a chord chart you type, like

```
"Chorus"|G|G|C,G|D|
```

into a bluegrass rhythm section (guitar boom-chuck, mandolin chop, upright
bass) that plays in the browser and can be exported as MIDI. An optional
melody, written in ABC notation, plays along on the guitar samples.

## How text becomes sound

```
chord chart text
   │  chart/parseArrangement.js   text → sections of bars of chords
   ▼
sections
   │  chart/timeline.js           where every chord and beat falls (in quarter notes)
   │  chart/swing.js              swing: each beat bent so its second eighth lands later
   │  chart/tempoCurve.js         the tempo lane's curve (a ritard), and the clock: song quarters ⇄ seconds
   │  chart/editTempoCurve.js     adding, moving and removing its points
   ▼
timeline
   │  instruments/performance.js  every instrument's notes (guitar.js, mandolin.js, bassline.js)
   │  instruments/band.js         those notes as sound: samples and the upright's synth
   │  instruments/tuneInstruments.js  what the tune's voices play on (recorded samples, played by tuneVoice.js, level-matched by sampleLoudness.js), picked per strip in components/mixer/instruments/
   │  instruments/strumPatterns.js  the guitar's strum patterns, as data
   │  instruments/articulation.js  pluck and graze (how the pick meets a string), as data; soundStart.js finds where a sample's sound begins
   │  instruments/sampleTuning.js  puts each guitar sample in tune as it plays (fixes in guitarSampleFixes.js, written by scripts/measureSampleTuning.js)
   │  styles/styles.js            the band's styles (Bluegrass, Celtic) as data: each has its time signatures (`times`: Celtic adds 6/8, 9/8, 12/8; the Bar tab offers the style's) and its own guitar-voicing generator (`voicing`: styles/bluegrass/bluegrassVoicing.js, styles/celtic/celticVoicing.js, which for now just calls bluegrass's). `chordBook.chordShape(name, style)` asks the style; `style` is passed down from the song through `preparePerformance` and `guitarChords`. A song's `style` is saved with it and picked in the Band lane's ⋯ menu (components/page/StyleSelect.svelte). Still bluegrass whatever the style: strums, bass, mandolin, chord-name checks (`hasShape`), the chord-places rule (`chart/chordPlaces.js`), Transcribe's time list
   │  instruments/seededRandom.js the repeatable random choices
   │  instruments/mandolin.js     off-beat chops, one per chord (songChops); yours from chopEdits.js
   │  instruments/guitarPlan.js   what the guitar plays on each chord (shape, booms, chucks, your notes, or a fill: notes you write for its last bars, `guitarFill.js`); yours from guitarEdits.js; guitar.js times it
   │  instruments/guitarBars.js   a run of chords' changes copied and pasted from another chord on
   │  instruments/guitarPatterns.js  one chord's guitar changes as a pattern, and onto another chord (the right hand, runs and fill moved by root); saved by storage/guitarPatterns.js
   │  instruments/guitarSamples.js  the band's guitar samples as a tune instrument
   │  instruments/chopSound.js    the chop's percussive sound: noise tk, closing filter, fade-out
   │  instruments/bassline.js     the band's own bass part, root and fifth (instruments/upright.js plays it)
   │  instruments/instrumentRanges.js  where each instrument naturally plays (the upright's range: the roll stripes notes outside it)
   │  bass/songBass.js            the bass in use: your edited line, else bassline.js's
   ▼
notes
   │  playback/scheduler.js       queues notes on the audio clock, a little ahead
   │  playback/metronome/         the click: its grid (song bars, or any meter alone), sounds, scheduler, the pendulum's swing, and the count-in (how many clicks, and playing them)
   │  mixer/mixerGraph.svelte.js  channels (trim, EQ, fader, pan, mute/solo) → reverb aux (+EQ) → master EQ → master
   │  $lib/audio/output/          output gain → true-peak limiter (loudness to −14 LUFS, never clips) → speakers
   ▼
sound
```

`playArrangement()` in `playback/livePlayback.js` is where playback starts:
it prepares the notes, builds the band and runs the scheduler. The Export
dialog renders the same band and mixer offline (`export/renderSong.js`) to
WAV files, or writes the MIDI file.

## How the page is put together

`src/routes/arranger/+page.svelte` is just an outline: it creates the page's
state and lays out a handful of components. The state is one `Arranger`
object (`state/Arranger.svelte.js`) made of small pieces:

| Piece                       | File                                    | Holds                                                                      |
| --------------------------- | --------------------------------------- | -------------------------------------------------------------------------- |
| `arranger.arrangement`      | `state/ArrangementState.svelte.js`      | chord chart text, tempo, capo, key, and what's worked out from them        |
| `arranger.loop`             | `state/LoopState.svelte.js`             | which bars play                                                            |
| `arranger.melody`           | `state/MelodyState.svelte.js`           | the ABC melody and everything read from it (parsed once per change)        |
| `arranger.bass`             | `state/BassState.svelte.js`             | the edited bass line's ABC, its score and the notes the band plays         |
| `arranger.player`           | `state/PlayerState.svelte.js`           | play/stop, and a problem to show                                           |
| `arranger.layout`           | `state/PageLayoutState.svelte.js`       | the player bar, which drawer is open (edit/mixer), the keypad              |
| `arranger.song`             | `state/SongState.svelte.js`             | which song is open; New, Open, Rename, saving itself                       |
| `arranger.recording`        | `state/RecordingState.svelte.js`        | recording along with the band, and the open song's takes                   |
| `arranger.receive`          | `state/ReceiveState.svelte.js`          | a song someone sent, waiting to be opened                                  |
| `arranger.parts`            | `state/PartsState.svelte.js`            | the parts as lanes: add (+ Inst, + Lane), name, remove, their order        |
| `arranger.audioEdits`       | `state/AudioEditsState.svelte.js`       | the picked clip on the Tracks page and every edit to it                    |
| `arranger.songBars`         | `state/SongBarsState.svelte.js`         | bars taken out of the whole song or empty ones put in                      |
| `arranger.virtuals`         | `state/VirtualEditsState.svelte.js`     | the picked bars on a virtual's lane and the tools that edit them           |
| `arranger.history`          | `state/EditHistory.svelte.js`           | Undo and Redo, each step named and placed: notes, clips, chops, tempo lane |
| `arranger.mandolin`         | `state/MandolinState.svelte.js`         | the mandolin's chop for each chord, the picked one, changing it            |
| `arranger.guitar`           | `state/GuitarState.svelte.js`           | the guitar's shape, booms and chucks per chord, changing them              |
| `arranger.chartFollowsTune` | `state/ChartFollowsTuneState.svelte.js` | chords typed in the ABC box, written into the chart after a pause          |

The Tracks page also makes its own `state/TracksCycleState.svelte.js` (the cycle, while you're on it).

Components get it with `useArranger()` (`state/context.js`), so nothing is
passed down through layers.

`arranger.song` (`state/SongState.svelte.js`) is which song is open: the
starter song as a new song until you save it (the song bar in
`components/song/` has New, Open and Save). `state/songFields.js` moves a
song between the page and a saved document, and
`state/autosave.svelte.js` saves the open song and the listening setup as they change: nothing ever asks about unsaved changes.

**Each of the song's three texts is read in one place.** The chart is parsed
in `ArrangementState`, the tune in `MelodyState` (`melody/readTune.js`) and
the edited bass in `BassState`, each once per change; features take what they
need from there (`arrangement.sections`, `melody.line`, `melody.voices`,
`bass.written`…) and never parse the open song themselves. abcjs loads after
the page (`state/abcjsLoaded.svelte.js`); the reads fill in when it arrives.
Only the sheet music draws the tune (`components/melody/SheetMusic.svelte`).

**Where to make a change:**

- **Behaviour** (what happens when you press Play, how the loop picks bars): in the state classes, or the plain functions they call (`chart/`, `melody/`, `export/`).
- **What's on screen:** in the one small component that shows it. Components hold almost no logic.
- **Looks:** in the theme tokens (`$lib/theme`).

## Good to know

- **Listening setups.** Every speaker and pair of headphones sounds
  different, so the EQs of every strip can be saved together as a listening
  setup ("iPhone speaker", "AirPods"), and each device remembers which one
  it uses and keeps it on for every song (`mixer/listeningSetup.svelte.js`).
  While a setup is in use, the EQs belong to it, not the song. A single
  strip's EQ can also be saved as a preset (`mixer/eqPresets.svelte.js`).

- **The starter song** (what a new visitor sees) is in `starterSong.js`: a chord chart and its ABC melody. Swap both to change it. New (`components/song/NewSongDialog.svelte`) asks the title, key and time first and starts `newSong(...)` (chart from `chart/newChart.js`).
- **Example songs** (the "New from…" menu in the song bar, with "A recording…" for Transcribe; `components/song/ExampleSongSelect.svelte`) are listed in `exampleSongs.js`; a new one is one entry.

- **All musical time is in quarter notes** from bar 1, so every part lines up.
  `chart/timeline.js` is the single source of truth; never assume a fixed bar length.
- **Tuning by ear:** musical choices (levels, timing feel, voicings) are named
  constants at the top of each file, so they're easy to adjust.
- **There are no automated tests.** To check pure logic (bass lines, timing,
  MIDI bytes), run a small Node script in a scratch folder. Stub the JSON and
  `mixer.svelte.js` imports, which need Vite/Svelte.
- The project's `CLAUDE.md` has more detail on each module.
