# Look, theming and tooltips

### Tooltips

- Every control gets a tooltip: `use:tooltip={TIPS.area.thing}` (`src/lib/tooltips/tooltip.js`). Shared controls take a `tip` prop instead (`Slider`, `ChannelFader`, `ToggleSwitch`). **When adding a control, add its tip.**
- All the wording is in `src/lib/tooltips/tips.js`, grouped by area: one or two plain sentences on what it does, for a non-technical user. Lists keyed by id (EQ bands, reverb controls, chord displays, visualiser views) follow the ids in the code that defines them.
- Behaviour (timings are constants at the top of `tooltip.js`): mouse after 1.5 s (the user found shorter annoying), then instant when moving straight to the next control (0.3 s); keyboard focus. **No tips on touch-only devices** (the user's call: hover isn't a thing on a phone or tablet), so the ? button and the Settings row carry `ui-hover-only` (in `theme/ui.css`, hidden under `@media (hover: none)`); an iPad with a trackpad can hover, so it keeps them. One shared bubble, a native `popover`, so it sits above dialogs. The ? button in the top bar (`tooltips/TipsToggle.svelte`) and Settings → General → Tips both turn them off (same setting, `settings.showTips`); the text stays on the control as `aria-description` for screen readers.
- Deliberately without tips: the phone music keypad (touch only anyway), text areas, plain Cancel/Close, and Settings rows that already show a description.

### Look and theming

- The look started as Soft UI, which the user has abandoned for contrast. **Every control must stand out clearly from what it sits on, in dark and light themes**: check it in a screenshot before calling it done (faders: a groove in `--color-ink-faint`, a raised cap with an `--color-ink-soft` border, `Slider.svelte`). The look now: cards and buttons are a lighter tone than the page (`--color-raised`) with a hairline border (`--color-line`) and a light drop shadow; wells and fields are a darker tone; the player bar has its own deeper blue (`--player-bar`). The colours come from five tokens at the top of `src/lib/theme/tokens.css`: background, text, accent, depth and roundness.
- **Depth** (the user hates a flat 2D look): raised things (cards, buttons, notes, the waveform, bars, dialogs) cast big drop shadows with a lit top edge and a shaded bottom (`--shadow-drop`, `-small`, `-floating`, `-up`, `-down`, `--shadow-bevel`, `--face-3d`, `--filter-drop` for shapes like the waveform); what holds content sinks in, like a mixing desk where controls stand up and the rest is set into the panel: wells, fields, meters, slider tracks, pressed or on buttons (`--shadow-sunk`, part of every `--shadow-inset*`), and big scrolling areas (`--shadow-sunk-deep`: the chord strip, and the piano roll and Transcribe's lanes through `ui-sunk-frame`, a shadow laid over the top because their rows would paint over an inset one). Settings → Appearance: a 3D depth switch, a drop shadow strength fader and a sink depth fader (`--drop` and `--sink` = switch × fader, multiplied into every shadow; both start at 2). **3D off means the whole app is flat**: `--depth-on` (tokens.css, 1 or 0) also fades the edge colours (`--shadow-light-edge`/`-dark-edge`; a border that should stay uses `--edge-dark`), the edge shading's reach and the player bar's keys; a new shadow written by hand multiplies its alpha by it, and an SVG effect (Transcribe's relief waveform, `ReferenceLane.svelte` `RELIEF`) is applied only while `settings.appearance.dropShadows`. Tried and taken off (the user turned them all off): frosted glass, glow, springy presses, tilt and sheen, gloss, a lit page, blur behind menus (commit 75b7734 has them). A new raised thing gets the bevel and a drop shadow.
- Everything else is derived from those tokens in CSS: softer text colours, the shadow edges (OKLCH lighter/darker of the background, so dark themes work), and the corner sizes.
- Settings → Appearance changes the same five variables at runtime (`theme.js` `applyTheme`, presets, and the WCAG contrast check).
- `applyTheme` saves every variable it sets (`bruegrass.firstPaint`), and `src/app.html` puts them back before the first paint, so nothing flashes the wrong colour; a new themed variable needs nothing there.
- Shared classes are in `src/lib/theme/ui.css`: `ui-card`, `ui-well`, `ui-button`, `ui-button-primary`, `ui-button-on`, `ui-field`, `ui-track-header` (a row's name cell in a track grid, `.picked` for the lane being edited), `ui-menu-item` and `ui-menu-heading` (a ⋯ menu's buttons and group headings). They're named for what a thing is, not how it looks.
- Components must not hard-code colours or corner sizes. Use the variables `--color-*`, `--shadow-*` and `--corner-*`, or Tailwind classes like `text-ink-soft`.
