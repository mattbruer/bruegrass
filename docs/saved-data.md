# Saved data and settings

## Saved data and settings

- `src/lib/storage/arrangements.js`: an arrangement is a plain document (`id`, `title`, `arrangement`, `abc`, `bass` (the edited bass line, '' = generated), `tab` (each part's TAB instrument and chosen strings), `partNames` and `laneOrder` (the Tracks page's lane order, ids top to bottom, [] for the usual order), `reference` (the recording it was transcribed from, `{ key, name }`, or null), `madeFrom` (the recording whose transcription it was sent from, or null), `tempo`, `tempoCurve` (the tempo lane's points, below), `swing` (where the second eighth of each beat lands, in percent: 50 straight, 66 triplet, 75 dotted), `capo`, `transpose`, `mix`, `createdAt`, `updatedAt`). Pages only go through this module, never storage directly. Today it's localStorage, a per-device copy that works offline. A database is planned (social features, realtime, PWA), so keep data serializable. **No versions or migrations** (the user's call): the app isn't live and the user is its only tester, so saved songs, drafts and takes may simply stop loading when a shape changes; change shapes freely, with no version numbers, upgrade steps or rescue code. (Two things look like versions and aren't: IndexedDB's own database version, which the browser needs to create stores, and `ANALYSIS_VERSION`, which recomputes Transcribe's cached beat analysis when the finder changes.)
- **Two layers of saving: this device, then the database.** Edits only ever write to this device (localStorage / IndexedDB), never to the network. When the database comes, a separate sync (`storage/sync.js`, not built) sends the songs changed since the last sync on its own schedule (every 30 s or so while working, on switching songs, when the page is hidden; one request for all of them) and brings down changes from other devices. `storage/arrangements.js` marks what's changed since the last sync; nothing above storage changes.
- **Songs save themselves** (the user's call: no Save button, no "discard?", no "pick up where you left off?"). `state/autosave.svelte.js` writes the open song (`SongState.saveNow`) and the listening setup in use 1 s after a change and at once when the page is hidden or goes away (an iPhone may unload it). Nothing asks before New, Open, an example, a received song or leaving: the open song is already saved (and `startNew`/`open` save it first).
  - The song bar is `components/song/` (name, Examples, Export, New, Open, **Rename**), and the logic is `state/SongState.svelte.js`.
  - The starter song and the examples are templates (`savedId` null): the first change makes one your own song, named for its tune (`suggestedName`), numbered if taken (`uniqueName.js`: "Amazing Grace 2"). Recording or adding a take makes a template yours at once (`keepAsYourOwn`). Saving waits for abcjs (`ready`), so the name is the tune's title.
  - The page opens on the song this device had open last (`storage/thisDevice.js` `thisDevicesSong`), else the starter song.
  - The mix is saved with the song (`mixSnapshot`/`applyMix`/`resetMix` in `mixer.svelte.js`).
  - Not built: undo. With autosave there's no "go back to saved"; a song history or undo is the way back from a mistake.
- EQ presets (`storage/eqPresets.js`, one strip's EQ) and listening setups (`storage/listeningSetups.js`, every strip's EQ) are documents in the same style, through `storage/collection.js`. Which setup this device uses is in `storage/thisDevice.js`, kept apart because it must never sync between devices.
- `src/lib/components/Dialog.svelte` is the shared dialog frame used by Settings, Rename and Open. Use it for any new dialog. `NameDialog.svelte` asks for a name (songs, presets, setups).
- `src/lib/settings/settings.svelte.js` holds preferences, grouped by Settings tab, and saves them (only values of the right type are restored).
- The panel is `SettingsPanel.svelte` (a dialog), around `SettingsTabs.svelte`, with one component per tab in `tabs/` and shared controls in `controls/`. To add a tab, add one line to `TABS` in `SettingsTabs.svelte`. On a computer, "Open in its own window" opens `/settings` (`settingsWindow.js`, the same tabs, no top bar) beside the app, so a change shows without closing it; windows keep in step through the `storage` event (`followOtherWindows` in `settings.svelte.js`).
